## 클래스

| index | 이름 | 무엇 |
|---|---|---|
| 0 | `amr` | 상대 TurtleBot4 |
| 1 | `worker_b` | 주황·가로줄 상의, 전고 285 mm |

**인덱스 순서가 이름 순이 아니다** — 데이터셋 `data.yaml` 이 알파벳순이라 `amr` 이 0 번이다.
클래스를 코드에서 다룰 때는 **이름으로** 거른다(`best_box()` 가 그렇게 돼 있다). 인덱스로 매핑하면 셋이 통째로 뒤바뀌는데,
검출은 정상으로 보이고 페어링만 전부 틀리는 형태로 나타난다.

`outfit_class` 는 **복장**을 가리킨다 (계약 2절, `WorkerDescriptor.msg`). 개체 이름이 아니다 —
AC-10 은 상의를 벨크로로 바꿔 달고 판정이 **옷을 따라가는지 몸통을 따라가는지** 보는 시험이므로,
클래스 이름이 복장을 가리켜야 결과를 해석할 수 있다.

## 학습 (I-003)

YOLO 패밀리 스윕 18건, RTX 4070, 9 h 19 m. 챔피언은 `yolo26s` @ 800 이었으나 **배포는 640** —
800 대비 mAP50-95 손실이 0.09 %p 인데 추론이 1.6 배 빠르다 (보고서 §7 비용·효익).

| | |
|---|---|
| run | `p2_yolo26s_img640_sgd_lr0.01_strong_cos` |
| 레시피 | `yolo26s.pt` · imgsz 640 · batch 16 · SGD lr0 0.01 · cos_lr · strong aug · 130 epochs · seed 42 |
| val | mAP50 0.9948 · mAP50-95 0.8161 · P 0.9931 · R 0.9948 |
| test (미사용 셋) | mAP50 0.9950 · mAP50-95 0.8026 — 과적합 징후 없음 |
| 혼동행렬 | **`amr` ↔ 작업자 오분류 0건.** 대각선 밖이 비어 있다 |

재현:

```bash
yolo train model=yolo26s.pt data=<dataset>/data.yaml \
    epochs=130 imgsz=640 batch=16 optimizer=SGD lr0=0.01 lrf=0.01 cos_lr=True seed=42
```

학습 라벨은 `steve`(=worker_a) · `ari`(=worker_b) 였고, 계약 이름으로 바꿔 저장했다.
가중치는 건드리지 않는다 — 클래스 이름은 체크포인트 안의 `model.names` dict 일 뿐이고,
신경망은 채널 인덱스만 출력한다 (교체 전후 파라미터 SHA-256 동일 확인).

### confidence

conf 스윕(val)에서 F1 최적은 0.4 지만 **0.5~0.6 을 쓴다.** F1 은 오탐과 미탐의 비용이 같다고 보는데
우리는 대칭이 아니다 — 미탐은 Lost 후 재탐지 절차가 설계돼 있고 K-04 로 측정되지만, **오탐은 오추종이고
AC-04 는 0건이 절대 기준**이다. 0.4 → 0.6 에서 오탐 6 → 2, 재현율은 1 %p 만 떨어진다.
값은 `config/perception.yaml` 의 `detect_conf` 가 단일 출처다.

### 색 편향 점검 (I-003, SOT '상의 휘도 맞춤')

데이터셋 bbox crop 통계 — **두 인형의 밝기 차이 0.6 %.**

| | 객체 crop 밝기 | 채도 S |
|---|---|---|
| `worker_a` | 143.6 | 26.6 |
| `worker_b` | 142.7 | 21.3 |
| `amr` | 76.0 | 24.4 |

모델이 밝기로 두 인형을 가른 것이 아니라는 실측 근거가 된다 (R-B9 반박). `amr` 이 확연히 어두운 것이
혼동행렬에서 오분류 0건이 나온 이유이기도 하다. 채도는 25 % 차이가 있으므로 알고 있을 것.
