| 항목 | 내용 |
|---|---|
| 문서 버전 | **v3.6** (2026-09-10) — **남은 미결을 모두 닫았다** (Q-5 · Q-13 · Q-14 · Q-16 확정 · Q-17 폐지) · **대기공간 측위 검증 마커(ArUco ID 4) 폐지.** 아래 「v3.5 → v3.6 개정 이력」 참조 |

## 1. 한 줄 정의와 요청 사항

> **"정비사를 따라다니며 공구를 지원하고, 필요한 자재를 작업 위치까지 자율 배송하며, 여러 대의 로봇을 통합 관제해서 — 정비사의 비가치 이동과 FOD 위험을 동시에 줄이는 시스템"**

**Phase 1이 답해야 할 질문 세 가지**

1. 작업별 복장이 구분되는 다수 작업자 중 **지정된 정비사를 신뢰성 있게 추종**하는가. (동일 작업복 조건은 Phase 2)
2. **두 대의 로봇**이 좁은 통로에서 교착 없이 운용되는가.
3. 사람·구조물에 대해 **무사고**가 성립하는가 — 인지·웹캠·네트워크 어느 것이 죽어도.

**요청 사항:** 3장 시나리오와 9장 수락 기준의 승인.

**의사결정자가 알아야 할 두 가지**

| | 내용 |
|---|---|
| ① | **미션 지표(≥90/95%)와 안전 지표(0건)는 성격이 다르다.** 미션 지표는 미달해도 개선 계획으로 논의할 수 있다. **안전 지표가 1건이라도 발생하면 Phase 1은 불합격이다.** |
| ② | **Phase 1은 "같은 옷을 입은 사람" 문제를 풀지 않는다.** 작업별 복장 2종을 전제로 착용형 태그 없이 외형 재식별을 한다(Q-1). 동일 작업복 조건은 Phase 2 과제로 남겼고, 그때까지는 신뢰도 미달 시 정지·대기하는 안전 규칙이 오추종을 막는다. |

#### 3.1.1 작업자 대체물 — 스케일 모델 정합

실증 아레나는 MDF 슬롯 조립 벽으로 만든 **축소 모델**이다. 여기에 실제 사람을 넣으면 ① 사람이 벽보다 4배 커서 벽이 가림 역할을 하지 못하고, ② OAK-D(렌즈 높이 23.5 cm, 9/6 실측)에는 다리만 보이며, ③ 동일 작업복 조건에서 하체는 사실상 구분 불가하다. 따라서 Phase 1의 "작업자"는 **스케일 인형을 얹은 RC카**로 정의한다.

| 항목 | 값 | 근거 |
|---|---|---|
| 스케일 | **약 1:4** `[팀 가정]` | TB4(Ø 34 cm) ≈ 1.4 m급 AMR, 벽 41 cm(실측) ≈ 1.6 m 파티션·비계, 인형 40 cm ≈ 1.7 m 작업자 |
| 인형 높이 | **≤ 40 cm** | 추종거리 0.5 m에서 OAK-D 수직 화각 안에 전신이 들어오는 상한 (0.235 + 0.5·tan 25° ≈ 0.47 m) |
| 형태 | **원통 3단 구조** (몸통 원통 + 어깨판 + 목 + 머리 구), 전고(RC카 포함, 바닥 기준) **실측 worker_a 265 / worker_b 285 mm** (9/6). 20 mm 차이는 아래 '사람 간 차이' 로 **의도된 것** — 스페이서로 맞추지 않는다 | 회전 대칭이라 360° 어느 각도에서도 실루엣이 같고, bbox 폭이 일정해 거리 추정이 안정적이다. 상세 치수·색은 SDD HW-09 |
| 두 인형의 관계 | **작업별 복장 2종** (예: 기체 정비 = 조끼 A, 전장 정비 = 조끼 B) + 사람 간 차이(키 20 mm, 몸통·어깨판·머리 지름) | 실제 MRO도 직군·협력사별로 조끼 색이 다른 현장이 있어 1차 조건으로 정당화 가능. **동일 작업복 조건(OR-2.1)은 Phase 2** — YOLO 난이도를 일정 안에 맞추기 위한 팀 결정 |
| 이동 | **원격 비례 조종 RC카**, 목표 속도 ≤ 0.3 m/s (≈ 사람 보행 1.2 m/s의 1:4). 조종자 숙련으로 속도 유지 | 반복성 확보. 조종 숙련 기준은 Q-17 |
| 식별 편향 방지 | 하의·머리 두 인형 동일, 상의 두 색의 **휘도를 맞춤**, 같은 프린터로 인쇄. **상의는 벨크로로 탈부착** | 모델이 밝기·차체가 아니라 상의를 학습하게 강제. 상의를 바꿔 달고 재시험하면 R-B9 에 대한 실증적 반박이 된다 |
| 검출 | YOLO 커스텀 클래스 `worker_a`·`worker_b` 재학습 (미니프로젝트 `car`·`dummy` 학습 파이프라인 재사용). 재식별 = 복장 클래스 + 색 히스토그램 | 부록 E |

**정직한 한계:** ① 인형은 강체라 시점·자세 변화가 없어 재식별이 실제 사람보다 쉽다. ② 복장 2종 조건은 동일 작업복 조건보다 쉽다. 따라서 Phase 1 결과는 사람 대상 성능의 **상한**이며, 실제 사람·동일 작업복·실제 높이의 AMR(또는 마스트 카메라)에서의 재검증을 Phase 2 진입 조건에 둔다.

### 3.4 이 시나리오가 실증하지 않는 것 (솔직한 한계)

- **축소 환경**이다. 실제 정비고의 조도 편차·광택 바닥·바닥 호스는 재현하지 않는다 → Pilot 대상.
- **작업자는 스케일 인형(RC카)** 이고 **복장은 작업별 2종**이다. 재식별 난이도가 실제 사람·동일 작업복보다 낮으므로 결과는 상한이다(3.1.1). 실제 사람·동일 작업복 재검증은 Phase 2.
- **적재는 시뮬레이션**이다. 사람이 싣고 내리는 인계 절차는 없다.
- **목적지는 고정 Waypoint(Z-05)** 다. 움직이는 정비사에게 배달하는 동적 랑데부는 Phase 2.
- **웹캠 2대는 PoC 인프라**다. 실제 현장 배치에 고정 카메라를 전제하지 않는다. E-5가 이를 증명한다.
- **생산성 KPI(이동시간 50% 감소 등)는 측정하지 않는다.** 베이스라인이 없는 환경에서는 판정 불가 → Phase 2.

**안전 계층 원칙 (타협 불가)**

> 정지와 회피는 **AMR 온보드 센서(LiDAR·범퍼)만으로** 성립한다. 재식별 모델, 웹캠1·2, Wi-Fi, 관제 PC 중 **어느 것이 죽어도 정지 동작은 유지**된다. 웹캠2는 "더 빨리 다시 찾게" 할 뿐, "안 부딪히게" 하는 데 관여하지 않는다.

이 원칙이 v0.2의 BR-T20·NFR-S.5를 Phase 1 구성에 맞게 구체화한 것이며, TS-14(결함 주입)와 E-5로 검증한다.

### 4.1 웹캠2 KPI 계측 최소 사양

방위 힌트에 이미 필요한 "사람 검출 + 바닥 호모그래피 + ROS2 퍼블리시" 위에 **기록과 오프라인 계산만** 얹는다. 실시간 요구 없음, 로봇 리소스 사용 없음.

| 지표 | 지상 진실 산출 방법 | 자동/수동 | 추가 공수 |
|---|---|---|---|
| 추종거리 오차 (K-01 보조, AC-05) | 웹캠2 사람 바닥 좌표 − 로봇 위치(`/amcl_pose`, LiDAR 측위라 RGB-D 사람 추적과 독립. 또는 로봇 상부 ArUco). 타임스탬프 동기 CSV → 시험 후 p95 계산 | 자동(오프라인) | 0.5일 |
| 오추종 / ID Swap (K-03, AC-04) | 로봇 로그의 Lost·재획득 시각 기준으로 웹캠2 영상을 **자동 클립** → 사람이 판정 | 반자동 | 교차 100회 ≈ 2~3시간 판정 |
| 접촉 (K-09, AC-01) | 시험 관찰자 기록 + 웹캠2 영상 확인 | 수동 | — |
| Lost 지속·재획득 시간 (K-04) | 로봇 상태 전이 로그(인지 무관 이벤트). 웹캠2는 "그 순간 대상이 실제로 시야 안에 있었는가" 확인용 | 자동 | — |

**전제:** 웹캠2 노드가 웹캠2 PC(PC-W2)의 ROS2 노드로 동작해 헤더 스탬프를 ROS 시각으로 찍는다(로그와 자동 동기). 영상 원본은 시험 세션 판정 후 폐기한다(R-10).

**Phase 1에서 웹캠2로 하지 않기로 한 것 — 장애물 정보의 계획 계층(costmap) 주입.** 구현은 가능하나(바닥 투영 → `map` 프레임 PointCloud2 → Nav2 obstacle layer, 2~3일 + 튜닝) 본 도면은 **경로가 하나뿐**(P1 병목, Z-09)이어서 미리 알아도 계획이 달라지지 않고, 투영 오차로 생긴 유령 장애물이 가장 좁은 Z-09를 막아 **개입을 늘릴** 위험이 있다. 대안 경로가 있는 Pilot 환경에서 Phase 2 훅으로 재검토한다(부록 D, BR-T32).

### 5.3 측정 정의 (판정 기준 고정)

| 용어 | 정의 |
|---|---|
| **추종 미션 1회** | S5 페어링 확정 → S9 종료 발행까지의 1세션. **Z-05→Z-07 이동 + Z-07 내 이동 3회 이상 + 교차 이벤트 2회 이상**을 포함해야 유효 미션이다 `[팀 가정]` |
| **추종 미션 성공** | 유효 미션이 **오추종 없이** 종료된 경우. 중간 Lost는 동일 대상으로 복구되면 성공 |
| **오추종 (ID Swap)** | AMR이 지정 작업자가 아닌 사람을 추종 대상으로 삼아 **이동한** 경우. 1건이라도 있으면 해당 미션 실패 + 별도 집계 |
| **교차 이벤트** | 타 작업자가 대상과 AMR 사이를 통과하거나 두 작업자가 1 m 이내로 근접한 1회 |
| **배송 미션 성공** | 요청 접수 → **요청 구역의 ArUco ID를 베이에서 검출**(오도착 판정 근거) → **T_lim 이내** Z-05 도착, 사람 개입 없음. 오도착·초과·개입은 실패로 집계 |
| **교착 자동 해결** | 2대 상호 진행 불가 진입 후 **사람 개입 없이 60초 이내** 통행 재개 `[팀 가정]` |
| **개입 (Intervention)** | 사람이 AMR의 정상 자율 동작 복원을 위해 수행한 조작 1회 — 재페어링, 수동 이동, 재시작, 견인, 수동 배송 대체. **안전 정책상 의도된 정지(E-4·E-6) 후의 자동 재개는 개입이 아니다** |
| **복귀 성공** | 종료 발행 후 **사람 개입 없이 T_ret 이내에 도킹이 완료된 경우.** 자동 재시도로 성공하면 성공으로 보되 재시도 횟수를 기록한다. 수동 도킹은 실패이며 개입으로도 계상한다. |
| **IPH** | 개입 횟수 / 총 운용 시간. 운용 시간 = S2 undock ~ S10 도킹 완료의 합 (충전 시간 제외) |
| **추종 유지율** | 정상 추종 상태 시간 / (미션 시간 − Standby 정당 구간). 작업자가 정지해 Standby로 들어간 시간은 분모에서 제외 |
| **접촉 사고** | AMR이 사람·타 AMR·구조물과 물리 접촉한 모든 사건. 손상 무관 1건 |
