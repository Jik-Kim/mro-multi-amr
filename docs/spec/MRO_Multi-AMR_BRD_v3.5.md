## 1. 비즈니스 목표

> **"정비사를 따라다니며 공구를 지원하고, 필요한 자재를 작업 위치까지 자율 배송하며, 여러 대의 로봇을 통합 관제해서 — 정비사의 비가치 이동과 FOD 위험을 동시에 줄이는 시스템"**

정비사가 공구·부품을 확보하려고 Tool Crib과 작업 구역을 반복 왕복 — 작업시간의 20~30% `[팀 가정 — 항공 MRO 린 정비 벤치마크(Wrench Time 외 이동·대기 35~42%) 기반 보수적 설정]`. 공구·부품 미회수는 FOD 위험이고, 로봇 대수가 늘면 관제 인력도 는다. 기존 대안은 이 공백을 못 메운다 — 수동 공구 카트는 이동시간이 그대로이고, AGV 는 고정 인프라를 전제해 작업 진행에 따라 환경이 바뀌는 정비고와 맞지 않으며, 단일 AMR 물류는 작업 위치가 움직이는 상황을, 단순 작업자 추종 로봇은 원거리 자재 요청과 다중 로봇 조정을 다루지 못한다.

Phase 1 은 이 공백을 **한 흐름(요청 → 배송 → 합류 → 추종)** 으로 닫는 것을 실증한다. 정비사가 관제센터에서 자재를 요청하면 AMR 이 창고에서 가져와 합류 지점에서 만나고, 이후 작업 위치까지 따라다닌다. 2대가 동시에 같은 흐름을 수행하며 통로·합류 지점에서 마주쳐도 사람 개입 없이 풀린다.

**Phase 1 이 답해야 할 질문 세 가지**

1. 작업별 복장이 구분되는 다수 작업자 중 **지정된 정비사를 신뢰성 있게 추종**하는가. (동일 작업복 조건은 Phase 2)
2. **두 대의 로봇**이 좁은 통로에서 교착 없이 운용되는가.
3. 사람·구조물에 대해 **무사고**가 성립하는가 — 인지·웹캠·네트워크 어느 것이 죽어도.

## 2. 프로젝트 범위

AMR 2대(TurtleBot4)와 작업자 2명(스케일 인형을 얹은 RC카), 고정 웹캠 2대, 관제 PC 로 구성한 축소 아레나에서 **2.4 의 10단계 시나리오와 2.5 의 예외 7종**을 실증한다. 작업자 등록(웹캠1) → 자재 요청 → 셔틀 배송 → 대기공간 합류·재식별 → 추종 → 예외 대응 → 작업 종료 → 순차 복귀·도킹까지가 한 회차다.

### 2.1 포함 범위

- 웹캠1 작업자 등록, 외형 재식별 페어링
- 요청 → 셔틀(고정 베이) → 대기공간 배송
- 지정 작업자 추종, 재획득(웹캠2 힌트), Standby
- 온보드 회피·안전 정지, 적재물 이탈 방지
- 2대 관제, 교착 해결, 운영자 명령, 개입 로깅
- **종료 시퀀스 → 즉시 추종 중단 → 순차 복귀·도킹**
- 생산성 KPI 측정 체계

### 2.2 제외 범위

**구현·시험하지 않는 것.** 본문에서 "Phase 2" 로 표기한 항목은 모두 여기에 속하며, 본 과제는 후속 일정을 약속하지 않는다.

- 얼굴 인식, 착용형 태그 (Q-1 결정에 따라 배제, 폴백 시 재검토)
- 동적 랑데부(움직이는 작업자에게 배송), 자동 적재·인계
- 공구 출고·반납 추적, 미반납 경고
- **KOZ(접근 금지 구역)**, 바닥 호스·케이블 통과, 저조도·광택 바닥 조건
- 장갑 조작 UI, Digital Work Order 연동
- 자동 충전 스케줄링, 도킹 실패 자동 복구(사람 개입 대체)
- 생산성 KPI 판정 (이동시간 50 % 감소 · 확보 정비시간 · 운반 70 % AMR · TAT, BR-C01~C03·C08) — 베이스라인 실측이 필요하다. Phase 1 은 측정 설계와 로그 스키마만 준비한다
- 실제 정비 구역에서의 병행 운용 (Pilot), 자동 요청, 배차 최적화, 안전 인증
- FOD 추적·신체 부담 경감·자산 재사용 목표 (BG-04 · BG-06 · BG-07)
- v0.2 의 제외 범위(정비 자동화, 로봇팔, 항공기 하부·잭업·연료 구역 진입, 인증 취득 등)는 그대로 유지한다

**본 실증의 한계 — 결과를 읽을 때 전제할 것.**

- **축소 환경**이다. 실제 정비고의 조도 편차·광택 바닥·바닥 호스는 재현하지 않는다 → Pilot 대상.
- **작업자는 스케일 인형(RC카)** 이고 **복장은 작업별 2종**이다. 재식별 난이도가 실제 사람·동일 작업복보다 낮으므로 결과는 상한이다(2.3). 실제 사람·동일 작업복 재검증은 Phase 2.
- **적재는 시뮬레이션**이다. 사람이 싣고 내리는 인계 절차는 없다.
- **목적지는 고정 Waypoint(Z-05)** 다. 움직이는 정비사에게 배달하는 동적 랑데부는 Phase 2.
- **웹캠 2대는 PoC 인프라**다. 실제 현장 배치에 고정 카메라를 전제하지 않는다. E-5가 이를 증명한다.

**작업자 대체물 — 스케일 모델 정합**

실증 아레나는 MDF 슬롯 조립 벽으로 만든 **축소 모델**이다. 실제 사람을 넣으면 ① 사람이 벽보다 4배 커서 벽이 가림 역할을 못 하고, ② OAK-D(렌즈 높이 23.5 cm)에는 다리만 보이며, ③ 동일 작업복 조건에서 하체는 사실상 구분 불가다. 따라서 Phase 1 의 "작업자" 는 **스케일 인형을 얹은 RC 카**로 정의한다.
- **스케일 약 1:4** `[팀 가정]` · 인형 전고 **≤ 40 cm** · 목표 속도 **≤ 0.3 m/s** (사람 보행 1.2 m/s 의 1:4)
- **작업별 복장 2종.** 두 인형의 하의·머리는 동일하게 두고 **상의 두 색의 휘도를 맞춰** 같은 프린터로 인쇄한다 — 밝기·차체가 아니라 상의를 학습하도록 강제하기 위해서다. 상의는 벨크로로 탈부착한다
- **정직한 한계.** 인형은 시점·자세 변화가 없어 재식별이 실제 사람보다 쉽다. 복장 2종 조건도 동일 작업복보다 쉽다. 따라서 Phase 1 결과는 **사람 대상 성능의 상한**이며, 실제 사람·동일 작업복에서의 재검증은 Phase 2 진입 조건에 둔다 (R-B9)

### 2.4 정상 흐름 — 10단계

각 단계는 **두 작업자·두 AMR이 동시에** 수행한다. 단계 번호는 시험·로그 ID로 그대로 쓴다.

## 5. 종속성 및 제약조건

### 5.1 종속성

- **AMR 2대** — TurtleBot4 (2D LiDAR · OAK-D RGB-D · Create3 범퍼·클리프·도킹). 자율주행(Nav2)·추종·온보드 장애물 회피·안전 정지·재식별 판정·대기·복귀를 맡는다
- **웹캠1** (출입구) — 작업자 등장 감지와 **외형 서술자 등록**. 신원 식별(얼굴)과 영상 장기 저장은 하지 않는다
- **웹캠2** (작업공간·P3 개구부) — 전역 사람 위치 추적 → **재탐지 방위 힌트**, 그리고 KPI 지상 진실(추종거리·오추종·접촉 판정). 장애물 회피·안전 정지에는 관여하지 않는다
- **관제 PC** — 미션 생성·배정, 상태 모니터링(≤ 2초, 단순 뷰어), 교착 우선순위, 작업 종료 → 복귀 명령, 로그·IPH 산출. DB 와 Fleet UI 를 포함한다
- **아레나** — MDF 슬롯 조립 벽, 창고 베이 A/B/C 의 ArUco 마커(도착 판정의 독립 근거), 도크 2기, 실측된 통로 폭 (2.3)
- **Wi-Fi** — 단절 시에도 AMR 의 추종·회피·정지는 성립해야 한다 (E-5)

### 5.2 제약조건

- **안전 계층 원칙 (타협 불가).** 정지와 회피는 **AMR 온보드 센서(LiDAR·범퍼)만으로** 성립한다. 재식별 모델, 웹캠1·2, Wi-Fi, 관제 PC 중 **어느 것이 죽어도 정지 동작은 유지**된다. TS-14(결함 주입)와 E-5 로 검증한다
- **계측 수단의 오차는 판정 기준의 1/3 미만**이어야 한다. 웹캠2 호모그래피 오차(0.11~0.27 m)는 추종거리 판정 기준 0.2 m 에 못 미치므로, 추종거리는 검출 노드의 대상 거리 로그로 판정한다 (7.1). 계측 사양은 SDD 6.2
- **Phase 1 은 "같은 옷을 입은 사람" 문제를 풀지 않는다.** 작업별 복장 2종을 전제로 착용형 태그 없이 외형 재식별을 한다. 동일 작업복 조건은 2.2
- **축소 환경·스케일 인형·시뮬레이션 적재**라는 전제 위의 결과다 (2.2 의 한계). 실제 사람·실제 정비고에서의 성능 상한으로 읽어야 한다
- **표본 수는 일일 시험 제약을 반영한 간이 검증 표본**이다 (7장). 대규모 표본(100회 이상)은 Phase 2
- Phase 1 미결 사항(Q-5 · Q-13 · Q-14 · Q-16 · Q-17)은 **전건 종결됐다 (9/10).** 결정 근거는 `BRD_changelog.md`

| **배송 미션 성공** | 요청 접수 → **요청 구역의 ArUco ID를 베이에서 검출**(오도착 판정 근거) → **T_lim 이내** Z-05 도착, 사람 개입 없음. 오도착·초과·개입은 실패로 집계 |
| **교착 자동 해결** | 2대 상호 진행 불가 진입 후 **사람 개입 없이 60초 이내** 통행 재개 `[팀 가정 — 산업용 FMS 로컬 정지 대기(5초) 및 우회·후진 기동(30~45초) 소요 감안]` |
| **개입 (Intervention)** | 사람이 AMR의 정상 자율 동작 복원을 위해 수행한 조작 1회 — 재페어링, 수동 이동, 재시작, 견인, 수동 배송 대체. **안전 정책상 의도된 정지(E-4·E-6) 후의 자동 재개는 개입이 아니다** |
| **복귀 성공** | 종료 발행 후 **사람 개입 없이 T_ret 이내에 도킹이 완료된 경우.** 자동 재시도로 성공하면 성공으로 보되 재시도 횟수를 기록한다. 수동 도킹은 실패이며 개입으로도 계상한다. |
| **IPH** | 개입 횟수 / 총 운용 시간. 운용 시간 = S2 undock ~ S10 도킹 완료의 합 (충전 시간 제외) |
| **추종 유지율** | 정상 추종 상태 시간 / (미션 시간 − Standby 정당 구간). 작업자가 정지해 Standby로 들어간 시간은 분모에서 제외 |
| **접촉 사고** | AMR이 사람·타 AMR·구조물과 물리 접촉한 모든 사건. 손상 무관 1건 |
