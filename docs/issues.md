### I-004

**벽 받침대(발)가 LiDAR 사각지대**

`mro_bringup` · 심각도 중 · 담당 주행 박병후·이시율 · 등록 2026-09-05 (PM)

- **내용·재현** — 받침대는 바닥에 붙어 있어 LiDAR(약 27~30 cm)에 안 잡힘 → SLAM 지도에는 없는데 실제 통로는 그만큼 좁음. 벽에 붙어 주행하면 범퍼 충돌
- **조치·남은 것** — 실측 표는 `docs/measurement_guide.md` §2. 받침대를 통로 바깥으로 돌리거나, Nav2 inflation 을 받침대 돌출폭 이상으로. **LiDAR 스캔 높이 실측 18.5 cm (9/6, I-005).** 위 '약 27~30 cm' 는 출처 없는 추정치였고 실제는 그보다 낮다 — 받침대는 바닥에 붙은 부품으로 18.5 cm 보다 낮아 **'사각지대' 전제는 성립한다**.
  **돌출폭 실측 완료 (9/6, 주행)** — P1 **받침대 없음** · P2 양쪽 각 3 cm(벽면 0.86 → 실통과 0.80) · P3 입구 5 cm + 안쪽 6.5 cm.
  가장 좁은 P1 에 받침대가 없어 병목 통과에는 부담이 없다. 대응은 `inflation_radius` 를 **0.25 로 올리는 것으로 주행 합의(9/6)** — 승인 후 양쪽 제어 PC 에 적용한다. 상세는 **I-009**.
  **해결 (9/6, PM).** 실측이 끝났고 남은 대응(inflation 0.25 적용·실주행 확인)은 I-009 가 맡는다 — 원인 하나에 이슈 하나.

### I-005

**벽 높이 vs OAK-D 높이 미측정**

`mro_bringup` · 심각도 상 · 담당 주행·인지 박병후·정정인 · 등록 2026-09-05 (PM)

- **내용·재현** — 벽이 카메라보다 낮으면 Z-06·Z-09 에서 가림(Target Lost)이 생기지 않아 E-1·TS-05 시나리오가 성립하지 않음
- **조치·남은 것** — 실측 표는 `docs/measurement_guide.md` §3. **3개 실측 완료 (9/6, 인지 정정인·민범진): LiDAR 18.5 cm · OAK-D 렌즈 23.5 cm · 작업자 전고(RC카+인형) worker_a 26.5 / worker_b 28.5 cm.** I-007 로 가림원이 교차 작업자로 바뀌었고 `26.5/28.5 > 23.5 > 18.5` 이므로 **E-1·TS-05 성립 확인.** 단 렌즈 대비 여유가 3~5 cm 뿐이라 가림원이 대상보다 로봇에 더 가까이 지나가야 한다(§3) — E-1 은 worker_b 를 가림원으로.
  **벽 상단 높이 41 cm 실측 (9/6, 주행).** `41 > 23.5 > 18.5` 로 벽이 렌즈보다 17.5 cm 높다 — 벽에 의한 가림도 성립한다. 4개 항목 모두 실측 완료로 종결.

- **조치·남은 것** — 둘 중 하나. ① **approach `FAILED` 는 미션 전이에서 뺀다** (`APPROACH_MISSION_STATES` 에서 제거, STATE 이벤트로만 남김) — follow_target 의 FAILED 는 노드 내부 사이클 실패이지 미션 실패가 아니다. 미션 FAILED 는 shuttle 출처(포기)·T_lim·운영자에서만 온다. ② `FAILED` 는 터미널로 두지 않고 `DONE` 만 터미널로 — 이후 정상 진행 상태가 오면 FAILED 에서 빠져나오게 한다. **PM 은 ①+② 를 권한다.** 주행에는 `shuttle/status = FAILED` 를 **포기할 때만** 내도록 I-024 todo 에 적어뒀다 (재시도 중이면 SHUTTLE 유지).
  **해결 (9/7, PR #18 김민준).** ①+② 그대로 — approach `FAILED` 는 미션 전이에서 빠지고 STATE 이벤트만, 터미널은 `DONE` 만. 회귀 테스트 3개 추가(접근 실패 후 복구→DONE, approach FAILED 는 이벤트만, FAILED 뒤 셔틀 진행 재개).
