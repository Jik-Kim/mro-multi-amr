## 그리는 규칙

STEP 3 두 장은 **교재 Day5 p.73 형식**을 따른다. 9/7 저녁에 이 형식으로 다시 그렸다.

**3-2 전체 기능 흐름 — PC 패널 + 가운데 DDS 버스**

- **PC 는 상자 채움색으로 나눈다.** 파랑 로봇3 · 보라 로봇4 · 주황 관제 · 초록 웹캠 · 회색 온보드.
  테두리는 전부 회색으로 통일한다 — 그래야 화살표 색과 섞이지 않는다.
- **화살표 색이 통신 종류다.** 파랑 실선 토픽 · 주황 파선 서비스 · 보라 굵은선 액션 · 빨강 안전 경로.
- **모든 화살표에 이름을 적는다.** 첫 줄이 토픽·서비스·액션 이름, 둘째 줄이 메시지 타입과 방향이다.
- **버스를 가운데 가로로 둔다.** PC 를 넘는 화살표가 전부 짧게 끝나고, 멀리 돌아가는 선이 없어진다.
- **상자에는 그 노드가 실제로 하는 일을 3~5줄 적는다.** 파라미터 값과 이슈 번호까지.

**3-1 시나리오 순서도**

- 상자 하나에 짧은 한 줄 · 판단은 마름모 + `Y` / `N` · 예외는 태그만 붙이고 내용은 아래 표에.
- 흐름이 길면 두 단으로 접고 `①` 로 잇는다.

**스크립트가 자동으로 잡아주는 것 셋** (`build_diagrams.py` 가 경고로 알려준다)

1. 글자가 상자보다 넓은지 — 마름모·육각형은 가운데가 좁아 실효 폭을 따로 센다
2. 화살표 라벨이 상자를 가리는지
3. 라벨끼리 겹치는지

**라벨은 상자보다 나중에 그린다.** 먼저 그리면 상자에 덮여 글자가 안 보인다.
안쪽 점선 밴드도 바깥 PC 컨테이너를 먼저 그려야 제목이 살아남는다.

## 고치는 법

그림은 **손으로 그리지 않고 스크립트가 만든다.** 좌표·상자 크기·연결선이 자동으로 맞춰지고,
문서와 값이 어긋나면 한 곳만 고치면 되기 때문이다.

```bash
# 내용을 고친 뒤
python3 tools/build_diagrams.py
```

스크립트는 글자가 상자 밖으로 넘치는지, 상자가 캔버스를 벗어나는지 검사해 경고한다.

draw.io 에서 직접 손볼 일이 있으면 `mro_design_diagrams.drawio` 를 열어 편집하고,
**그 결과를 스크립트에도 반영한다.** 반영하지 않으면 다음 생성 때 되돌아간다.
