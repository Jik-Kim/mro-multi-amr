| 파일 | 내용 |
|---|---|
| `system_flowchart.drawio` | **정본.** draw.io 로 연다 (새 창에서 단독으로) |
| `system_flowchart_preview.svg` | 빠르게 훑어보는 용도. 브라우저로 연다 |
| `../../tools/flowchart/` | 이 그림을 만드는 생성기. **손으로 고치지 않고 여기를 고친다** |

```bash
cd tools/flowchart

```

**두 검사가 모두 0건이 아니면 내보내지 않는다.**

## 왜 이 형식인가

**받는 팀은 우리 BRD · SDD · 이슈 문서를 보지 못한다고 본다. 이 그림 하나만 보고 같은 것을
만들 수 있어야 한다.** 강사님 SDD 0차 5쪽 형식을 따랐다.

---

## 구성

```
              ┌ PC1 웹캠1 ┐
PC4 · AMR     │ PC2 웹캠2 │     PC5 · AMR
 (/robot3)    │ PC3 관제  │      (/robot8)
              │ 터틀봇3   │
              └ 터틀봇8   ┘
```

**바깥 테두리 하나 = PC 한 대 · 안쪽 테두리 하나 = 그 PC 에서 도는 노드 하나 ·
노드 안은 그 노드가 하는 일의 순서다.**

**우리가 만들지 않은 것도 같은 PC 에서 돌면 그린다.** AMR 제어 PC 는 터미널 네 개다 —
① 위치 추정 ② 보기 화면 ③ 길찾기(Nav2) ④ 우리 온보드 노드 여섯 개.
①③ 은 순서도 대신 **주고받는 것과 기동 순서**만 적는다 (`docs/setup.md` 가 원본).

가운데 열에 관제·웹캠·터틀봇을 두고 좌우에 로봇 제어 PC 를 놓았다. 토픽을 가장 많이
주고받는 짝(관제 ↔ 로봇)이 서로 이웃이라 선이 짧다. **PC4 와 PC5 는 똑같다** — 노드도
토픽도 같고 이름 앞만 `/robot3` · `/robot8` 로 갈린다.

PC 마다 노드를 **한 줄로** 세운다. 한 줄이면 모든 노드가 PC 양쪽 테두리에 닿아
PC 를 건너는 화살표가 옆으로 곧장 이어진다 — 위아래로 크게 돌 일이 없다.

## 그리는 규칙

### 1. 상자에는 무슨 일을 하는지 **우리말로**

**함수 이름 · 변수 이름 · 파라미터 이름을 쓰지 않는다.** 받는 팀은 우리 코드를 보지 않는다.

> ✗ `detection_confirm_s 0.3` · `hsv_hist(crop)` · `jpeg_quality 80`
> ✓ `트랙 확정 0.3초 연속 보이면` · `색 지문을 뽑는다` · `화면 압축 품질 80`

**ROS 토픽 이름과 메시지 타입은 그대로 쓴다** — 받는 팀이 실제로 그 이름으로 붙여야 한다.

### 2. 노드마다 「바꿀 수 있는 값」 상자를 둔다

숫자만 적지 말고 **왜 그 값인지**를 같이 적는다. 그래야 받는 팀이 자기 환경에서 다시 정할 수 있다.

> 푸는 거리 0.38 m — 0.45 로 두면 좁은 목 안에서 어느 방향으로 돌아도 풀리지 않는다 (통로 반폭 0.395 m)

### 3. 가짜 시작 타원을 두지 않는다

「관제가 배정을 알려오면」 같은 칸은 실제로 존재하지 않는다. **보내는 상자에서 받는 상자로
곧장 화살표를 잇는다.** 생성기에서는 받는 칸에 `a='이름'` 을 달고 화살표가 그 이름을 가리킨다.

### 4. 선 색이 토픽 갈래다

| 색 | 갈래 |
|---|---|
| 파랑 | 식별 · 대상 (웹캠 등록 · `target/*`) |
| 보라 | 미션 명령 (`mission/assigned` · `mission/finish`) |
| 청록 | 상태 보고 (`approach/status` · `shuttle/status` · `/fleet/zone_event`) |
| 회청 | 장비 원본 (`oakd/*` · `scan` · `battery_state` · `amcl_pose`) |
| 주황 파선 | 서비스 (`/fleet/zone_token` · 관제 서비스) |
| 빨강 | 안전 (`safety/estop` · `cmd_vel`) |
| 회색 | 노드 안에서 다음 칸으로 (점선 = 앞 칸으로 되돌아간다) |

### 5. 한 토픽이 여럿에게 가면 줄기 하나 + 갈림점

**이름과 타입은 줄기에 한 번만** 적고, 갈래에는 받는 노드가 그것으로 무엇을 하는지만 적는다.
갈래마다 이름을 적으면 다른 토픽처럼 보인다.

### 6. 토픽 이름은 **제 선 위에** 말풍선으로

흰 바탕 + 선과 같은 색 테두리. 상자를 덮고 있는 선이 그 토픽의 선이다.
글자끼리 겹치면 `spread.py` 가 세로로 밀어낸다.

### 7. 사양은 외부 장비 상자에만 — 빠짐없이

받는 팀이 같은 장비를 고를 수 있을 만큼 적는다 (설치 위치 · 시야 · 주기 · 해상도 · 연결 방식).
노드 상자에는 사양을 적지 않는다.

### 8. 내부 문서 번호를 쓰지 않는다

`I-036` · `Q-26` · `PR #45` · `계약 4절` 은 받는 팀이 못 본다. 내용을 한 줄로 풀어 쓴다.

### 9. 갈래는 **어디서 시작해 어디서 끝나는지** 둘 다 밝힌다

- **첫 칸** — 스스로 도는 것(타이머 · 기동 · 감시)이 아니면 들어오는 화살표가 있어야 한다.
- **마지막 칸** — 내보내거나 · 다른 칸으로 넘기거나 · 「여기서 끝」이라고 밝히거나 셋 중 하나.

같은 노드 안에서 갈래끼리 넘기는 것도 화살표로 그린다 (회색 점선). ROS 토픽이 아니라
프로그램 안의 값이라는 뜻이다. 예 —

- 웹캠2 검출 갈래가 그린 화면 → 화면 발행 갈래가 가져간다
- 인지의 배정 갈래가 건 **짝짓기 기준값** → 본 흐름의 「내 담당 기준값이 있는가?」 가 읽는다
- 추종의 비상정지 갈래 → 풀리면 멈췄던 단계로 돌아간다

`check_flow.py` 가 두 가지를 다 검사한다.

### 10. 선이 상자를 뚫으면 내보내지 않는다

`check.py` 가 검사한다. 화살표는 **상자 왼쪽 통로 → 노드 사이 빈 줄 → PC 사이 통로** 순으로
돌게 되어 있고, 이 세 곳은 원래 상자가 없는 자리다.

## 고치는 법

내용은 전부 `tools/flowchart/nodes.py` 한 파일에 있다.

```python
S('시작 문구')                              # 타원
D('하는 일')                                # 네모
A('판단인가?', no='아니오일 때 하는 일', back=3)  # 마름모 + 빨간 상자 + 3번 칸으로 되돌아감
O('내보내는 것 — 토픽 이름 · 타입 · 담는 것')     # 계약 상자
V('외부 장비 · 바꿀 수 있는 값')                # 회색 상자
```

- 한 노드는 `chains=[[...], [...]]` — 갈래(콜백·타이머)마다 한 줄
- `a='이름'` 을 달면 PC 를 건너는 화살표가 그 칸에 직접 꽂힌다
- 배치·색·글꼴은 `engine.py` 와 `render.py` 가 정한다. **노드마다 다르게 두지 않는다**
- PC 를 건너는 화살표는 `arrows.py` 에 있다. 출처는 `docs/interfaces.md` 4절 계약이다

고친 뒤 반드시:

```bash
python3 main.py && python3 check.py
```

**`check.py` 가 0건이 아니면 그대로 내보내지 않는다.**

## 값의 출처

숫자는 노드 소스와 `config/*.yaml` · `params/*.yaml` 에서 읽어 적었다.
값이 바뀌면 `nodes.py` 를 고치고 다시 만든다. **코드가 원본이고 그림은 사본이다.**
