| 파일 | 내용 |
|---|---|
| `step5_graph_w1.svg` | **웹캠1 갈래 (형식 견본).** 담당자별로 자기 갈래를 이 형식으로 그려 합친다 |
| `mro_design_diagrams.drawio` | draw.io 편집본 |

---

## 왜 이 형식인가

**받는 팀은 우리 BRD · SDD · 이슈 문서를 보지 못한다고 본다. 이 그림 하나만 보고 같은 것을
만들 수 있어야 한다.** 건설 도면이 그렇듯이.

그래서 이 그림에는 내부 문서 번호를 쓰지 않고, 코드를 안 봐도 되게 적는다.

---

## 그리는 규칙

### 1. 구조 — PC 안에 노드, 노드 안에 순서도

```
┌ PC-W1  웹캠1 PC ─────────────────────────────┐
│  ┌ webcam_register  작업자를 등록하는 프로그램 ┐│
│  │      ( 작업자 등록 시작 )   ← 타원          ││
│  │              ↓  카메라 화면 한 장           ││
│  │      [ 사람 검출 ]          ← 네모          ││
│  │              ↓  화면 속 사람 위치 · 복장 종류 ││
│  │      < 등록 대상 복장인가? > ← 마름모        ││
│  └────────────────────────────────────────────┘│
└────────────────────────────────────────────────┘
```

타원 = 시작 · 네모 = 하는 일 · 마름모 = 판단 · 빨간 네모 = 갈라진 쪽의 처리.

### 2. 상자에는 **무슨 일을 하는지 우리말로**

**함수 이름과 변수 이름은 쓰지 않는다.** 받는 팀은 우리 코드를 보지 않는다.

> ✗ `descriptor_cb(msg)` · `PairingGate.register(...)` · `hsv_hist(crop)`
> ✓ `상의 색 지문 뽑기` · `등록된 색 지문을 기준값으로 저장`

**이름만 지우는 것으로는 부족하다. 그 안에서 실제로 무엇을 하는지 단계로 펴야 한다.**

> 관제의 배정 콜백을 처음에 `작업자에게 로봇 배정` 한 상자로 뒀다. 실제 코드에는
> **두 명이 거의 동시에 등록되면 모일 때까지 기다렸다가 번호순으로 붙이는** 대기 명단
> 로직이 있었다. 한 상자로 두면 받는 팀은 선착순으로 만들어 버린다. 지금은 일곱 단계다.

### 3. 화살표에는 **무엇이 흘러가는지**

**PC 안의 화살표도 마찬가지다.** 상자만 이어 놓으면 무엇이 넘어가는지 알 수 없다.

```
[ 사람 검출 ]
      ↓  화면 속 사람 위치 · 복장 종류 · 확신도
< 등록 대상 복장인가? >
      ↓  예 · 대상 복장인 사람만
[ 같은 사람에게 추적 번호 유지 ]
```

### 4. PC 를 건너는 화살표에는 **ROS 토픽 이름과 메시지 타입**

토픽 이름은 그대로 쓴다 — 받는 팀이 실제로 그 이름으로 붙여야 한다.

```
/webcam1/worker_descriptor
토픽 · WorkerDescriptor
1초마다 다시 보낸다
```

| 종류 | 색 |
|---|---|
| 토픽 | 파랑 |
| 서비스 | 주황 파선 |
| 액션 | 보라 |
| 안전 경로 | 빨강 |
| 함수 호출 (같은 프로그램 안) | 초록 |
| ROS 밖 (장치) | 회색 — ROS 토픽이 아님을 밝힌다 |

**한 토픽을 여럿이 받으면 화살표를 여러 개 그리지 않는다.** 줄기 하나로 내보내고
갈림점에서 나눈다. 이름과 타입은 줄기에 한 번만 적는다 — 세 번 적으면 다른 토픽처럼 보인다.

### 5. 갈라지는 쪽도 **끝을 밝힌다**

`아니오` 쪽이 어떻게 되는지 없으면 흐름이 그 상자에서 끊긴 것처럼 보인다. 셋 중 하나로 적는다.

- **되돌아간다** — 어디로 돌아가는지 화살표와 이유를 적는다 (`0.1초 뒤 다음 화면부터 다시 본다`)
- **다른 단계로 이어진다** — 이어지는 곳까지 화살표를 그린다
- **여기서 끝난다** — 상자 안에 `이번 소식은 여기서 끝` 처럼 밝힌다

### 6. 사양은 **외부 장비 상자에만 — 빠짐없이**

장비는 화살표로 설명할 상대가 없다. **받는 팀이 같은 장비를 고를 수 있을 만큼** 적는다.

- 설치 위치와 시야 범위
- 촬영·측정 주기, 해상도 (지정하지 않고 장치 기본값을 쓴다면 **그 사실을 적는다**)
- 연결 방식, 여러 대일 때 무엇을 고르는지
- ROS 토픽으로 오는지, 프로그램이 직접 읽는지

노드 상자에는 사양을 적지 않는다. 노드가 하는 일은 순서도로 드러난다.

### 7. 내부 문서 번호를 쓰지 않는다

`I-016` · `Q-26` · `PR #19` · `계약 4절` 은 **받는 팀이 못 본다.** 내용을 한 줄로 풀어 쓴다.

> ✗ `CAP_PROP_BUFFERSIZE = 1 (I-016)`
> ✓ `오래된 화면이 쌓이지 않게 한 장만 들고 있는다`

### 8. 배치 — 발행은 왼쪽, 받는 곳은 오른쪽에 세로로

받는 노드를 왼쪽·아래에 두면 선이 그림을 크게 돌아 읽을 수 없게 된다.
칸을 건너는 선은 꺾이는 자리를 **통로 안**에 둔다. 칸 한가운데서 꺾이면 그 칸과
관계가 있는 것처럼 보인다.

### 9. 빈 자리를 두지 않는다

상자 폭 · 컨테이너 폭 · 캔버스 크기를 전부 **내용에서 계산**한다. 고정 폭으로 두면
짧은 문장이 빈 자리를 크게 차지한다. 라벨에는 배경 상자를 두지 않는다 — 배경이
지나가는 화살표를 덮어 선이 끊겨 보인다. 글자에 흰 테두리만 두른다.

## 만드는 법

```bash
python3 tools/build_diagrams.py
```

`step5_graph_w1()` 이 견본이다. 자기 갈래는 같은 방식으로 함수를 하나 더 만들어
`main()` 의 `diagrams` 에 추가한다.

스크립트는 아홉 가지를 검사해 경고한다 — 글자 넘침, 라벨이 상자를 가림, 라벨끼리 겹침,
라벨이 화살촉을 덮음, 라벨이 컨테이너 경계에 걸침, 라벨이 캔버스 밖으로 나감,
선이 남의 상자 뒤로 지나감, 화살촉이 다른 상자에 덮임, 화살촉 둘이 같은 점에 꽂힘.

**경고가 하나라도 남으면 그대로 내보내지 않는다.**

draw.io 로 직접 편집했으면 그 결과를 스크립트에도 반영한다. 반영하지 않으면 다음 생성 때 되돌아간다.

**draw.io 여백** — 화면에서 없애려면 `View → Page View` 체크 해제.
내보낼 때만 없애려면 `File → Export as…` 에서 **Size: `Diagram`** · **Border Width: `0`**.

## 값의 출처

토픽 이름과 타입은 `contract_topics()` 가 `docs/interfaces.md` 4절 표를 파싱해 준다.
**계약이 원본이고 그림은 사본이다.** 그림에 토픽 이름을 손으로 적지 않는다.

설정값은 해당 패키지의 `config/*.yaml` 에서 읽어 그린다. 새 숫자를 적을 때는
그 값의 원본이 어디인지 먼저 보고, 가능하면 읽어온다.
